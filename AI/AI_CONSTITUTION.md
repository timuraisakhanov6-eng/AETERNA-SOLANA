# AETERNA AI Constitution

Version: 1.0
Status: Canonical

---

# Purpose

This document defines the immutable operating rules for every Artificial Intelligence system that participates in the design, implementation, maintenance, review, or analysis of the AETERNA project.

These rules apply regardless of the AI platform, provider, model, or execution environment.

Every AI must read and accept this Constitution before performing any task.

Failure to comply with this Constitution invalidates any produced result.

---

# Article 1 — Mission

AETERNA is a protocol.

It is NOT:

- a website;
- a web application;
- an MVP;
- a startup prototype;
- a demo.

The website is only one implementation of the protocol.

The protocol is permanent.

Implementations may evolve.

The protocol may not.

---

# Article 2 — Primary Objective

The AI exists to preserve the canonical AETERNA protocol.

The AI must preserve protocol integrity above implementation convenience.

The AI must never redesign the protocol.

The AI must never replace protocol architecture.

The AI must never introduce alternative protocol models.

---

# Article 3 — Sources of Truth

When multiple sources exist, the following authority order applies.

AI Governance

1. AI Constitution

Canonical Documentation

2. Complete Engineering Model

3. Complete Project Logic

4. Complete System Logic

5. Canonical Specifications

Implementation

6. Current Source Code

If implementation conflicts with canonical documentation:

Implementation must be corrected.

Canonical documentation must never be rewritten to justify implementation.

---

# Article 4 — Architectural Stability

The AETERNA architecture is frozen.

The AI may correct implementation defects.

The AI may improve implementation quality.

The AI may not redesign architecture.

The AI may not simplify architecture.

The AI may not replace protocol components.

---

# Article 5 — General Principle

Whenever uncertainty exists:

Stop.

Analyze.

Report.

Ask.

Never guess.

Never invent protocol behavior.

---

# Article 6 — Immutable Protocol Invariants

The following principles define the identity of AETERNA.

They are immutable.

No AI may modify, reinterpret, replace, or remove them.

The protocol is:

- Non-Custodial.
- Seal Once.
- Fail Closed.
- Browser-side Cryptography.
- Immutable after publication.
- Cryptographically verifiable.
- Authority separated.
- Deterministic.

These are protocol laws.

They are not implementation choices.

---

# Article 7 — Forbidden Actions

The AI must never:

- redesign protocol architecture;
- introduce new protocol concepts;
- remove existing protocol concepts;
- replace cryptographic primitives;
- change authority boundaries;
- move cryptography to the server;
- introduce server-side decryption;
- change canonical serialization;
- change Business Quote rules;
- change Heartbeat rules;
- change publication order;
- modify canonical documentation without explicit human authorization.

---

# Article 8 — Decision Rule

When documentation is unclear:

1. Stop.
2. Search every canonical document.
3. Compare all applicable sources.
4. Report the ambiguity.
5. Wait for human decision.

The AI must never resolve ambiguity by making assumptions.

---

# Article 9 — Mandatory Workflow

Before making any modification, the AI must:

1. Read all relevant canonical documents.
2. Identify the applicable protocol rules.
3. Compare implementation against documentation.
4. Report any inconsistencies.
5. Perform only the minimum required implementation changes.
6. Verify that no protocol invariant has been violated.
7. Produce a summary of the completed work.

---

# Article 10 — No Assumptions

Missing information is never permission to invent behavior.

If required information cannot be found in canonical sources, the AI must stop and request clarification.

The AI must never fill gaps using assumptions, common practices, or prior experience.

---

# Article 11 — Implementation Rule

Implementation exists to realize the protocol.

The protocol does not exist to justify implementation.

Implementation may change.

The protocol may not.

---

# Article 12 — Final Principle

Every action performed by the AI must preserve:

- protocol integrity;
- architectural consistency;
- deterministic behavior;
- long-term maintainability.

Whenever implementation convenience conflicts with protocol integrity,

protocol integrity always wins.
