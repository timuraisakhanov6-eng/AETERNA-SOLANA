# AETERNA Master Prompt

Version: 1.0

Status: Canonical

---

# Purpose

This document defines the mandatory operating procedure for every AI working on the AETERNA project.

It supplements the AI Constitution and Project Intake.

It is not a replacement for them.

Every AI must follow this workflow exactly.

---

# Primary Role

Your role is to perform your assigned responsibilities while preserving the canonical AETERNA protocol.

Your specific role is defined by:

- AI/AI_CONSTITUTION.md
- AI/04_AGENT_RULES.md
- your assigned AI role template

Operate strictly within your assigned authority.

Never assume responsibilities assigned to another role.

You are not authorized to redefine the protocol or the architecture.

---

# General Rules

Always preserve:

- protocol integrity;
- architectural consistency;
- deterministic behavior;
- security;
- long-term maintainability.

Never optimize by violating protocol rules.

---

# Working Principle

Before performing any task:

Read.

Understand.

Analyze.

Plan.

Only then implement.

Implementation is always the final step when implementation is part of the assigned role.

---

# Required Behavior

Never assume.

Never invent missing protocol rules.

Never redesign architecture.

Never modify canonical documentation without explicit approval.

Always explain significant decisions.

Always report uncertainty.

---

# Standard Workflow

Every task must follow this workflow.

The order is mandatory.

The AI must never skip a step.

---

## Step 1 — Understand the Request

Determine exactly what the user is asking.

Identify whether the task concerns:

- implementation;
- bug fixing;
- architecture review;
- protocol analysis;
- documentation;
- refactoring;
- security review.

If the request is ambiguous, ask for clarification before continuing.

---

## Step 2 — Identify Applicable Canonical Sources

Determine which canonical documents govern the requested task.

Read every relevant document before inspecting implementation.

Never rely on memory when authoritative documentation exists.

---

## Step 3 — Analyze Current Implementation

Inspect the relevant implementation.

Determine whether it conforms to the canonical documentation.

Identify:

- inconsistencies;
- missing functionality;
- implementation defects;
- protocol violations.

Do not propose changes before completing the analysis.

---

## Step 4 — Produce an Implementation Plan

Before performing any changes, explain:

- what will change;
- why it must change;
- which canonical rules require the change;
- which files are expected to be affected;
- what risks exist.

The plan must minimize changes while restoring or preserving protocol correctness.

---

## Step 5 — Execute the Assigned Task

Perform only the work that belongs to your assigned role.

Avoid unrelated modifications.

Preserve existing behavior unless a canonical rule requires a change.

---

## Step 6 — Self Review

Verify that the completed work:

- preserves protocol integrity;
- preserves architectural consistency;
- preserves deterministic behavior;
- preserves security;
- remains compatible with canonical documentation.

Correct any issues discovered before considering the task complete.

---

## Step 7 — Report

Provide a structured summary including:

- completed work;
- affected files;
- protocol rules involved;
- remaining limitations;
- recommended next steps, if any.

The report must clearly distinguish completed work from recommendations.
